# Архитектура и карта кода

STM32 опрашивает MAX31856, преобразует 4–20 мА через частотный AD7741 и вычисляет AC RMS ACS712. PID задаёт долю включения пакетного периода, логика контроллера применяет ограничения и аварии. EEPROM хранит параметры и состояние восстановления, Modbus предоставляет чтение и проверяемые команды. Периферийные прерывания не выполняют всю прикладную логику.

| Узел | Где искать |
|---|---|
| Управление, STOP/AUTO/MANUAL, реле, прогрев | `firmware/app/controller.c` |
| PID, anti-windup, производная | `firmware/app/pid.c` |
| Масштабирование и RMS | `firmware/app/measurement.c` |
| Modbus и валидация команд | `firmware/app/modbus.c`, `firmware/docs/PROTOCOL.md` |
| Настройки и диапазоны | `firmware/app/config.def`, `firmware/scripts/register_map.py` |
| EEPROM, CRC и миграция | `firmware/app/storage.c` |
| Физические выводы/периферия | `firmware/Core/Src/board.c`, `firmware/docs/HARDWARE.md` |
| ПК: транспорт → сервис → worker → окно | `apps/controller/protocol.py`, `service.py`, `worker.py`, `ui.py` |
| Видео: захват → декодер → геометрия → API | `apps/thermal_monitor/capture.py`, `vendor/uti260b`, `model.py`, `alignment_geometry.py`, `api.py` |
| LB02A: поток экрана и клавиши | `apps/calibrator_lb02a/esp32_display_viewer.py`, `lb02a_control.py`, `bridge/src` |

Два HEX-переключателя задают адрес 1…247. Условия записи и полномочия режимов проверяет сам регулятор. ПК не должен считать отправленный пакет подтверждением EEPROM: требуется статус и повторное чтение. Атомарная запись уставки/допусков и полная запись настроек различаются; см. карту команд.

Стендовая связь организована по ролям, без фиксированных COM-номеров. USB загрузки может связать земли измерительных устройств; в подтверждённых сериях он отключался. Для видео используются свежесть и отдельные временные метки, аппаратная синхронизация камер отсутствует.
