# Стенд · Терморегулятор CH1

Запуск из корня: `python run.py controller`. Собственное окружение также возможно: `pip install -r requirements.txt`, затем `python app.py` в этой папке.

Порт выбирается в окне; адрес задают шестнадцатеричные переключатели на приборе. Modbus RTU 38400/8E1, текущий протокол 2.4 с 47 параметрами. При подключении выполняется чтение, без автоматического нагрева. Окно показывает уставку, рабочую уставку, фактическую температуру, ток, мощность, ошибки и график. Регистры и единицы берутся из `registers.json`, совпадающего с картой прошивки.

Доступны восемь термопар, внутренняя/внешняя компенсация, калибровка тока и 4–20 мА, PID, период 2…300 с, пределы, ручная мощность и функции реле. Допуски относятся к реле; точность регулирования определяется PID и объектом.

Общая запись конфигурации переводит в STOP и проверяет EEPROM повторным чтением. Уставка и допуски могут запоминаться атомарно во время работы. Режимы AUTO/MANUAL/STOP и ручная мощность сохраняются в приборе. При `COMM_TIMEOUT_MS=0` закрытие окна оставляет автономную работу, при ненулевом тайм-ауте отправляет STOP. Эти правила следует учитывать при удалённом управлении.

CLI: `python app.py --status` читает последний снимок запущенного окна. `python app.py --snapshot --port PORT --address 1 --output state.json` напрямую читает прибор и выходит; `PORT` заменяется выбранным портом. Одновременно порт может занимать только один клиент. `--connect --port PORT` подключает GUI при запуске, но не включает нагрев.

Журнал измерений находится в `captures`, служебный статус — `.runtime/live.json`; эти каталоги не публикуются. Подробности работы: [QUICKSTART](../../docs/QUICKSTART.md), [протокол](../../firmware/docs/PROTOCOL.md), [инструкция](ИНСТРУКЦИЯ.txt).

Для CLI-примеров из этой папки используйте `python ../../env.py` вместо `python`, чтобы запускать их в окружении, установленном общим setup.py.
