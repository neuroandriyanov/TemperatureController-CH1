# Начать работу с проектом вместе с ИИ

## Подготовить контекст

Откройте распакованную папку проекта в среде разработки с ИИ-помощником. Дайте ему доступ к исходникам этой папки. Начните с README, AGENTS.md и базы `knowledge`. Личная история чата для продолжения не нужна и в комплект не включена.

Первый запрос можно сформулировать так:

> Изучи README.md, AGENTS.md, knowledge/index.json и firmware/docs/PROTOCOL.md. Опиши архитектуру CH1, текущие ограничения и какие данные подтверждают твои выводы. Проверь источники командой python scripts/knowledge.py --check. Пока работай только с файлами, без соединения с приборами.

Затем установите зависимости и выполните офлайн-проверки по QUICKSTART. Предоставьте помощнику вывод ошибки, если сборка не проходит; не заменяйте компилятор или версию прошивки догадками. Для программ ПК используется изолированное окружение, выбранное setup.py, для STM32 — Arm GNU Toolchain, для моста LB02A — PlatformIO.

## Типовые задачи

**Изменение протокола:** «Добавь параметр …; сначала покажи связанные config.def, регистры, ограничения и миграцию EEPROM. Сохрани совместимость и проверь граничные значения». Карта генерируется, её копия в приложении ПК должна совпадать побайтно.

**Разбор опыта:** «Пересчитай raw/pid60_hold5_02.json, отдели AUTO от ожидания и STOP, сравни первые и последние 300 секунд. Приведи исходный файл и критерий отбора; не заполняй пропуски тепловизора».

**Продолжение стендовой работы:** сначала сообщите реальные устройства, схему соединения, порт/адрес, положение датчика, нагрузку и разрешённое действие. Пример формулировки — «прочитать параметры без записи»; включение нагрева или прошивка должны быть отдельной явно заданной задачей. Не копируйте номера портов из чужой установки.

## Интерфейсы для помощника

| Программа | Интерфейс |
|---|---|
| Терморегулятор | `apps/controller/app.py --status` — статус открытого окна; `--snapshot --port PORT --address N` — прямое чтение. Для записи есть DeviceService и документированный Modbus; GUI и второй клиент не могут одновременно владеть портом |
| Видео/тепло | `apps/thermal_monitor/control.py`: состояние, кадры, точки, сохранение. Токен автоматически читается из локального `.runtime/api.json` |
| LB02A | Запуск с `--control-port 8768`, затем loopback `/state`, `/frame.png`, `/key`; подтверждать нажатия свежим экраном |
| Прошивка | `apps/stm32_programmer/app.py --operation … --port PORT`, с резервной копией и проверкой; BOOT0/RESET физические |

Технические команды являются примерами интерфейсов, а не разрешением включать оборудование. Никакой облачный аккаунт или API-ключ для самих программ стенда не требуется.

## Вести знания

Сначала ищите подтверждение в исходниках, затем в схеме и измерениях. Если данные расходятся, сохраните оба источника и статус `needs_verification`. Для нового опыта записывайте: дату/версию, схему, настройку приборов, критерий достижения, временные метки, сырой журнал, фото и условия остановки. Отдельно формулируйте гипотезу и план проверки.

Новый результат дополняет базу, а не стирает старый. Не выдавайте лабораторное сравнение за метрологическую поверку. Особенно: наружный корпус не равен кристаллу симистора, ±10 °C реле не равны точности PID, подтверждённая документация не равна подтверждённой физической реализации.
